## Method and data-handling calls made by this stream

| Time | Issue | Decision | Reason | Source |
|---|---|---|---|---|
| 16:30 | Slack timestamps carry no year. | Year is taken from the export header line. Messages are ordered by month, day and time. The weekday is never used. `when` is quoted verbatim in citations. If the header is missing, messages are listed as undated and not used for ordering. | Ruling C1. | `slack_export.md:L3`, `slack_export.md:L4` |
| 16:30 | What is a "thread" in a flattened export? | Messages in the same channel on the same day, after the seed message. | The importer does not expose the `---` separators and may not be edited. Same channel and day reproduces every thread in this export. | `slack_export.md:L4` |
| 16:30 | How is confidence produced? | One rule for every claim, in code: LOW if a core check fails, MEDIUM if only flag checks fail, HIGH if none fail. Checks are computed from the parsed data and printed with PASS or FAIL. Confidence is per claim, not per question. | A single level per question would hide that "what the P&L lists" is clean while "what was paid" is unverifiable. | `00_START_HERE.md:L56-L57` |
| 16:35 | When is status evidence too old to support "current state"? | Core check: latest status evidence within 14 days of the export date (`stale_after_days` in config). Here it is 3 days. | A threshold is needed for the rule to be computable. 14 days is one leadership sync cycle in this bundle. This is an assumption, labelled as one. | `meeting_notes/leadership_sync_2026-06-11.md:L3`, `meeting_notes/leadership_sync_2026-06-11.md:L47` |
| 16:35 | A unit can contain several status words (for example a freeze message that mentions "approved"). | Fixed priority, in config: LIFTED, FROZEN, QUESTION, DEFERRED, SCOPE, APPROVED. The matched word is printed next to each label so a reader can audit it. | Deterministic and visible. Negation is not parsed (see limits in `repo:ask/README.md`). | `slack_export.md:L66 [#leadership | Dana Whitfield | Wed Jun 10, 8:47 AM]`, `meeting_notes/leadership_sync_2026-06-11.md:L15` |
| 16:35 | If a later message reports the duplicate as confirmed. | The tool reports that a confirmation is claimed and quotes it. It does not judge which way it went and still shows both figures, because the P&L file still carries both rows. | Keyword matching cannot tell "confirmed duplicate" from "confirmed two contracts" reliably. | `slack_export.md:L152 [#finance | Maya Fortin | Mon Jun 2, 10:47 AM]` |
| 16:35 | Rows with an amount that is not a plain number (currency symbol, blank). | Shown as written, excluded from sums, and the "every line item is numeric" core check fails, which makes the as-listed claim LOW. | A partial sum must not look like a clean total. | `pnl_q1_2026.csv:L26` |
